## 一、技术选型总览

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| Web 框架 | FastAPI | 异步、自动 OpenAPI 文档 |
| ASGI 服务器 | Uvicorn | 生产建议 `--workers` + gunicorn |
| 语言 | Python 3.11+ | |
| 业务数据库 | MySQL 8.0 | 关系数据、业务表 |
| 向量数据库 | Milvus | 知识单元 embedding 存储与检索 |
| ORM | SQLAlchemy 2.0 (async) | 异步 ORM 标准 |
| 数据库驱动 | aiomysql | MySQL 异步驱动 |
| 迁移工具 | Alembic | Schema 版本管理 |
| 缓存 / 消息队列 | Redis (redis-py) | FAQ 缓存、Token 黑名单、限流计数、Redis Stream |
| 定时任务 | APScheduler | FAQ 挖掘、知识缺口聚合（进程内调度） |
| 认证 | python-jose (JWT) + passlib (bcrypt) | 双 Token |
| 限流 | 自实现令牌桶 + Redis | 见 §8 |
| 配置管理 | pydantic-settings | `.env` 加载 + 类型校验 |
| 依赖管理 | uv | 快速、锁文件 |
| 测试 | pytest + pytest-asyncio + httpx | |

> ⚠️ **驱动修正说明**：MySQL 场景下不使用 `asyncpg`（PostgreSQL 专用），统一使用 `aiomysql`。
> ⚠️ **Milvus 说明**：由于关系库与向量库分离，知识单元的向量索引数据独立存储在 Milvus collection 中，通过 `unit_id` 关联；向量同步采用「失败重试 + 状态标记」保证最终一致（见 §9.2）。

分层原则：
- `models`（领域层）不依赖任何 Web 框架，仅 SQLAlchemy 声明式映射。
- `repositories` 只做数据访问，不含业务判断。
- `services` 承载业务规则（权限、状态机、幂等）。
- `api` 只做参数校验、调用 service、组装响应。

## 四、数据模型设计（MySQL DDL）

> 完整字段语义与索引策略见《后端详细需求说明书》§2，此处给出 MySQL 落地 DDL 要点与差异。

### 4.1 DDL 关键点

- 字符集 `utf8mb4`，排序 `utf8mb4_unicode_ci`。
- 主键统一 `BIGINT UNSIGNED AUTO_INCREMENT`。
- 时间字段 `DATETIME(3)` 支持毫秒，默认 `CURRENT_TIMESTAMP(3)`。
- JSON 字段用 MySQL `JSON` 类型。
- `status` 枚举用 `TINYINT` + 注释，避免数据库枚举难扩展。

### 4.2 表清单（对应 models）

| 表名 | 说明 | 关键索引 |
| --- | --- | --- |
| `users` | 用户 | `uk_username`、`idx_department` |
| `departments` | 部门 | `idx_parent` |
| `roles` | 角色 | `uk_role_code` |
| `user_roles` | 用户-角色 | `uk_user_role`、`idx_role` |
| `role_permissions` | 角色权限 | `uk_role_perm` |
| `knowledge_units` | 知识单元 | `uk_unit_code`、`idx_category_status`、`idx_creator` |
| `unit_permissions` | 数据权限 | `idx_unit`、`idx_target` |
| `qa_access_logs` | 访问日志 | `idx_user_time`、`idx_session`、`idx_created` |
| `faqs` | FAQ | `idx_status`、`idx_related` |
| `knowledge_gaps` | 知识缺口 | `idx_status`、`idx_asked` |

### 4.3 SQLAlchemy 模型约定

```python
# app/models/base.py

    pass

# 示例：users
class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)

    created_at: Mapped[datetime] = mapped_column(DateTime, default=func.now())
    updated_at: Mapped[datetime] = mapped_column(DateTime, default=func.now(), onupdate=func.now())
```

## 五、认证与鉴权（JWT 双 Token）

### 5.1 Token 策略

- **Access Token**：JWT，有效期 30min，通过 JSON 响应体返回（`data.access_token`），请求头 `Authorization: Bearer <token>`。
- **Refresh Token**：JWT，有效期 7d，存于 **HttpOnly Cookie**（`refresh_token`），用于 `/api/auth/refresh` 换发新 Token（接口契约预留，实现见下）。

### 5.2 签发与校验（`core/security.py`）

```python
def create_access_token(subject: str, claims: dict) -> str: ...
def create_refresh_token(subject: str) -> str: ...
def decode_token(token: str) -> dict: ...  # 抛 JWTError
def hash_password(pwd: str) -> str: ...    # bcrypt
def verify_password(pwd: str, hashed: str) -> bool: ...
```

### 5.3 当前用户依赖（`core/deps.py`）

```python
async def get_current_user(
    token: str = Depends(oauth2_scheme),
    db: AsyncSession = Depends(get_db),
) -> User:
  pass
    # 1. 解码 token 2. 校验 Redis 黑名单 3. 查用户 4. 校验 status==1
```

### 5.4 RBAC 操作权限拦截

```python
def require_permission(code: str):
    async def checker(user=Depends(get_current_user), db=Depends(get_db)):
        perms = await get_user_permissions(db, user)   # 缓存到 Redis
        if code not in perms:
            raise AppError(40300, "无操作权限")
        return user
    return checker
```

权限码约定：`knowledge:create`、`knowledge:update`、`knowledge:delete`、`knowledge:query`、`ai:access`。

## 六、数据权限引擎（核心）

### 6.1 规则（四维 OR，仅本部门）

用户对知识单元可访问，满足任一：
1. `unit_permissions` 含 `target_type='global'`；
2. 含 `target_type='department'` 且 `target_id` == 用户 `department_id`（**不继承上级部门**）；
3. 含 `target_type='role'` 且 `target_id` ∈ 用户角色 ID 集合；
4. 含 `target_type='user'` 且 `target_id` == 用户 `id`。

### 6.2 实现（`services/permission_engine.py`）

```python
async def check_units(db, user: User, unit_ids: list[int]) -> tuple[list[int], list[int]]:
    """返回 (authorized_unit_ids, unauthorized_unit_ids)"""
    if not unit_ids:
        return [], []
    # 1. 查 global 授权的 unit_id
    # 2. 查 department 授权（user.department_id 精确匹配）
    # 3. 查 role 授权（user 角色集合）
    # 4. 查 user 授权（user.id）
    # 5. 汇总 OR 结果
```

> 该引擎同时服务于两个入口：
> - `POST /api/knowledge/check-permissions`（供智能体调用，传入 `user_id` + `unit_ids`）；
> - AI 问答服务内部直接调用（传入当前登录用户）。
> 权限判定逻辑只在一处实现，避免两套口径。

## 七、模块实现要点

### 7.1 认证模块（auth）
- `POST /api/auth/login`：校验密码 → 签发双 Token → 返回 `access_token`/`user_info`/`permissions`。
- `POST /api/auth/logout`：Access Token 加入 Redis 黑名单（TTL=剩余有效期）。
- `POST /api/auth/refresh`：校验 Refresh Cookie → 换发新 Access Token。
- `GET /api/auth/me`：返回当前用户信息与权限。

### 7.2 组织架构模块（org）
- 部门树：一次查询全部部门 → 内存组装树（数据量小）。
- 用户 CRUD、角色 CRUD、权限分配（全量覆盖写 `role_permissions`）。
- 删除约束：有子部门/成员/被角色引用的不允许删除（抛 40900）。

### 7.3 知识单元模块（knowledge）
- 导入：`multipart` 上传 → 校验类型/大小 → 生成 `task_id` → 落库为「处理中」任务 → 异步解析（线程池/后台任务）→ 更新进度。
- 解析（占位）：文件类型识别 + 文本抽取 + 按标题/段落切片为知识单元（初版对 md/txt 做基础解析，pdf/docx 预留接口）。
- 向量同步：解析成功后调用 embedding（Mock）→ 写入 Milvus，失败标记重试。
- 权限配置：事务覆盖写 `unit_permissions`，即时生效。
- 批量删除：逻辑删除（`status` 置删除态）+ 幂等。

### 7.4 AI 问答模块（ai，Mock）
- `POST /api/ai/chat/stream`：SSE 流式返回。
  - 校验登录态 → 记录会话 → Mock 召回若干 `unit_id` → 调用权限引擎过滤 → 组装 SSE 事件流。
  - 事件类型：`token`（增量文本）、`citation`（引用）、`permission_denied`（未授权提示）、`done`（含 token 统计）。
  - 异步投递 `qa_access_logs` 到 Redis Stream。
- 会话管理：`GET /api/ai/sessions`、`GET /api/ai/sessions/{session_id}`。

### 7.5 看板模块（dashboard）
- 聚合查询 `qa_access_logs`，指标/榜单/趋势三类接口。
- 数据量大时考虑物化视图或定时聚合表（预留）。

### 7.6 知识沉淀模块（settlement）
- FAQ 推荐列表、审核（状态机：仅 `pending_review` 可流转）、已发布库、缺口列表与建档。
- 审核通过 → 写入 Redis FAQ 缓存（见 §9.1）。

## 八、限流与安全

### 8.1 令牌桶限流（`utils/rate_limit.py`）

自实现令牌桶，Redis 后端（Lua 保证原子性），作为 FastAPI 依赖或中间件：

| 接口 | 限流 |
| --- | --- |
| `/api/auth/login` | 5 次/分/IP |
| `/api/ai/chat/stream` | 10 次/分/用户 |
| `/api/knowledge/import` | 10 次/时/用户 |
| 其他 | 100 次/分/用户 |

触发返回 `42900`。

### 8.2 敏感数据脱敏（`utils/redaction.py`）
- 密码仅存 bcrypt 哈希，任何接口不回传 `password_hash`。
- 日志中间件对 `password`、`token`、`access_token` 字段脱敏。
- 响应序列化时过滤 `password_hash` 等字段。

### 8.3 幂等（`utils/idempotency.py`）
- 导入：文件 MD5 去重。
- 权限批量配置：按 `unit_id` 覆盖写 + 事务。
- FAQ 审核：状态机校验防重复流转。

### 8.4 其他
- 上传：扩展名 + MIME 白名单、大小限制、随机文件名防路径穿越。
- SQL 注入：参数化查询（SQLAlchemy 默认）；XSS：回答 Markdown 渲染前清洗。

## 九、Redis Stream 消费者与定时任务

### 9.1 FAQ 缓存（`services/faq_cache.py`）
- 审核通过 → `SET faq:{id}`（JSON）+ 语义匹配键。
- 问答入口优先匹配 FAQ 缓存，命中直接返回标准答案。

### 9.2 日志消费者（`workers/stream_consumer.py`）
- 生产者：AI 问答完成后 `XADD qa_logs`。
- 消费者：独立进程/协程 `XREADGROUP` → 批量写 `qa_access_logs` → ACK。
- 保证主链路不因日志写入阻塞。

### 9.3 定时任务（`workers/scheduler.py`，APScheduler）
| 任务 | 周期 | 逻辑 |
| --- | --- | --- |
| FAQ 挖掘 | 每日凌晨 | 对 `qa_access_logs` 语义去重 + 频次聚合 → 达阈值生成 `faqs`（`auto_mined`/`pending_review`） |
| 缺口聚合 | 每日凌晨 | 召回相似度低于阈值的提问 → 聚类 → 生成/更新 `knowledge_gaps` |

> 说明：初版 FAQ 挖掘/缺口识别采用基于关键词/向量相似度的简化聚类（依赖 Milvus），真实 LLM 语义聚类后续接入。

## 十、异常与统一响应

- 统一响应：`{"code": 0, "message": "success", "data": ...}`。
- 全局异常处理器（`core/exceptions.py`）：
  - `AppError(code, message, http_status)` 业务异常；
  - 未捕获异常 → `50000` + 日志，不回传堆栈。
- 错误码表见《前后端接口契约（API蓝图）.md》。
