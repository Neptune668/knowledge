## 1. 技术栈选型

| 领域 | 选型 | 说明 |
| --- | --- | --- |

## 3. 数据模型设计

### 3.1 表关系总览

- `departments` 通过 `parent_id` 自关联构成部门树。
- `users.department_id` → `departments.id`（一人一部门）。
- `user_roles`：用户与角色多对多。
- `role_permissions`：角色与权限码多对多，`permission_type` 区分 `menu` / `operation`。
- `unit_permissions`：知识单元与四类数据权限实体（`global`/`department`/`role`/`user`）。
- `qa_access_logs`：问答访问日志，JSON 字段存储召回/授权/未授权单元 ID 列表。
- `faqs` / `knowledge_gaps`：知识沉淀与缓存。

### 3.2 建表 SQL 要点

字段以需求文档第 4 节为准，关键补充：

## 4. 核心模块设计

### 4.1 认证鉴权模块

- 密码哈希：`passlib[bcrypt]`，存储 `password_hash`。
- JWT：`python-jose` 签发，`HS256` 算法，Payload 含 `sub`（用户 ID）、`exp`、`type`。
- 权限拦截：基于 `Depends` 的 RBAC 校验器，从 `role_permissions` 读取权限码，拦截菜单/按钮级操作。
- 用户状态管理：`status` 字段控制启用/停用，停用用户登录拒绝、已签发 Token 立即失效。
- 重置密码：管理员可重置任意用户密码（不校验旧密码），支持首次登录强制改密（可选扩展）。

### 4.1.1 角色模型

系统预置三类角色（`role_code` 区分），职责如下：

| 角色 | role_code | 核心职责 |
| --- | --- | --- |
| 系统管理员 | `admin` | 用户/角色/部门 CRUD、菜单与操作权限分配、看板与 Token 监控 |
| 知识管理员 | `knowledge_admin` | 知识单元导入/编辑/删除、数据权限配置、FAQ 审核发布、缺口维护 |
| 普通用户 / 提问者 | `user` | AI 问答，按数据权限获取知识内容 |

- 操作权限（`role_permissions.permission_code`）采用 `资源:动作` 编码，如 `user:create`、`knowledge:delete`、`ai:chat`、`dashboard:view`、`faq:review`。
- `permission_type` 区分 `menu`（菜单可见性）与 `operation`（按钮/接口级），前端据此动态渲染菜单与按钮。

```python
# app/core/security.py
def create_access_token(user_id: int) -> str:
    expire = datetime.utcnow() + timedelta(minutes=settings.ACCESS_TOKEN_EXPIRE)
    payload = {"sub": str(user_id), "exp": expire, "type": "access"}
    return jwt.encode(payload, settings.SECRET_KEY, algorithm="HS256")

def get_current_user(token: str = Depends(oauth2_scheme)) -> User:
    payload = jwt.decode(token, settings.SECRET_KEY, algorithms=["HS256"])
    return user_service.get_by_id(int(payload["sub"]))

def require_permission(code: str):
    def checker(user: User = Depends(get_current_user)):
        if not org_service.has_permission(user.id, code):
            raise HTTPException(403, "无操作权限")
        return user
    return checker
```

### 4.2 数据权限引擎（核心）

四类实体 `global` / `department` / `role` / `user`，**OR 逻辑**（满足任意一种即放行）。

匹配规则补充：

- `global`：任意用户均可访问。
- `user`：`target_id == user_id` 精确匹配。
- `role`：`target_id` 命中用户任一角色。
- `department`：`target_id` 命中用户所属部门**或其任意祖先部门**（子部门继承父部门的授权）。

```python
# app/services/permission_engine.py
async def check_units(user_id: int, unit_ids: list[int]):
    """返回 (authorized_unit_ids, unauthorized_unit_ids)"""
    # 1. 获取用户所属部门与角色
    dept_id = await user_service.get_department_id(user_id)
    dept_chain = await org_service.get_department_chain_ids(dept_id)  # 含自身+祖先
    role_ids = await user_service.get_role_ids(user_id)

    # 2. 查询这些知识单元的全部权限记录
    perms = await unit_permission_repo.list_by_units(unit_ids)

    authorized, unauthorized = set(), set(unit_ids)
    for p in perms:
        hit = (
            p.target_type == "global"
            or (p.target_type == "department" and p.target_id in dept_chain)
            or (p.target_type == "role" and p.target_id in role_ids)
            or (p.target_type == "user" and p.target_id == user_id)
        )
        if hit:
            authorized.add(p.unit_id)
    return list(authorized), list(unauthorized - authorized)
```

> 默认状态下知识单元无任何权限记录，故默认拒绝；仅当命中任一条权限记录才放行。

### 4.3 LangGraph 工作流编排（后续实现，本阶段预留）

> ⚠️ 本阶段**不重点实现**知识入库与检索。以下为后续版本的设计预留：通过抽象接口与占位节点保证接口契约稳定，待后续补充真实节点逻辑即可，不影响上层服务与接口。

知识库的**导入**与**检索**两条链路规划以 LangGraph `StateGraph` 编排。每个节点为独立、可替换的纯函数/异步函数，节点间通过共享 `State`（TypedDict）传递数据，可观测中间状态、便于插拔增强节点。

#### 4.3.1 共享状态定义

```python
# app/workflows/state.py
from typing import TypedDict, Annotated, Literal
from langgraph.graph.message import add_messages

class IngestionState(TypedDict):
    files: list             # 上传文件
    parsed_docs: list       # 解析后的原始文本
    chunks: list            # 切片结果
    embeddings: list        # 向量
    unit_ids: list          # 入库后的知识单元 ID

class RetrievalState(TypedDict):
    question: str
    session_id: str
    user_id: int
    messages: Annotated[list, add_messages]   # 多轮对话消息
    recalled_units: list                      # 召回候选单元
    authorized_units: list                    # 鉴权通过单元
    unauthorized_units: list                  # 无权限单元
    context: str                              # 拼装后的上下文
    answer: str                               # 最终回答
    route: Literal["faq_cache", "retrieve", "rewrite"]
```

#### 4.3.2 知识导入工作流（ingestion_graph）

对应需求 7.1「文档上传 → 解析 → 切片 → 向量化 → 入库」。

```python
# app/workflows/ingestion_graph.py
from langgraph.graph import StateGraph, END

def build_ingestion_graph():
    g = StateGraph(IngestionState)
    g.add_node("parse", parse_node)          # 解析文档 → parsed_docs
    g.add_node("split", split_node)          # 切片 → chunks
    g.add_node("embed", embed_node)          # 向量化（调用外部 API）→ embeddings
    g.add_node("persist", persist_node)      # 写库 + 向量索引入库 → unit_ids
    g.set_entry_point("parse")
    g.add_edge("parse", "split")
    g.add_edge("split", "embed")
    g.add_edge("embed", "persist")
    g.add_edge("persist", END)
    return g.compile()

ingestion_graph = build_ingestion_graph()
```

```python
# app/workflows/nodes/ingestion_nodes.py
async def parse_node(state: IngestionState) -> IngestionState:
    state["parsed_docs"] = [await parser.parse(f) for f in state["files"]]
    return state

async def embed_node(state: IngestionState) -> IngestionState:
    state["embeddings"] = [await embedding_client.embed(c.text) for c in state["chunks"]]
    return state

async def persist_node(state: IngestionState) -> IngestionState:
    state["unit_ids"] = await knowledge_service.create_units(state["chunks"], state["embeddings"])
    await vector_store.upsert(state["unit_ids"], state["embeddings"])
    return state
```

#### 4.3.3 检索问答工作流（retrieval_graph）

对应需求 7.2，在召回质量不足时通过条件边回环「改写问题」重试。

```python
# app/workflows/retrieval_graph.py
from langgraph.graph import StateGraph, END

def build_retrieval_graph():
    g = StateGraph(RetrievalState)
    g.add_node("faq_cache", faq_cache_node)        # FAQ 缓存命中判断
    g.add_node("retrieve", retrieve_node)          # 混合召回
    g.add_node("authorize", authorize_node)        # 权限鉴权
    g.add_node("build_context", build_context_node)
    g.add_node("generate", generate_node)          # LLM 流式生成
    g.add_node("rewrite", rewrite_node)            # 召回不足时改写问题
    g.set_entry_point("faq_cache")

    # FAQ 命中直接返回，未命中走检索
    g.add_conditional_edges("faq_cache", route_faq,
        {"retrieve": "retrieve", "answer": "generate"})
    g.add_edge("retrieve", "authorize")
    g.add_edge("authorize", "build_context")
    g.add_edge("build_context", "generate")
    # 召回质量不足 → 回环改写重试，否则结束
    g.add_conditional_edges("generate", route_retry,
        {"rewrite": "rewrite", "end": END})
    g.add_edge("rewrite", "retrieve")
    return g.compile()

retrieval_graph = build_retrieval_graph()
```

```python
# app/workflows/nodes/retrieval_nodes.py
async def retrieve_node(state: RetrievalState) -> RetrievalState:
    state["recalled_units"] = await retrieve_hybrid(state["question"])  # 向量 + 关键字
    return state

async def authorize_node(state: RetrievalState) -> RetrievalState:
    authorized, unauthorized = await check_units(state["user_id"],
                                                 [u.id for u in state["recalled_units"]])
    state["authorized_units"] = [u for u in state["recalled_units"] if u.id in authorized]
    state["unauthorized_units"] = unauthorized
    return state
```

#### 4.3.4 检索策略：混合召回 + 重排

- 向量召回：`embedding_client` 计算 query 向量，`vector_store` 取 Top-K。
- 关键字召回：PostgreSQL 全文检索（`tsvector`）或 BM25 兜底。
- 融合：RRF（Reciprocal Rank Fusion）合并两路结果去重排序。
- 条件回环：当 Top-1 相似度低于阈值时，进入 `rewrite` 节点改写问题重召回（限制最大重试次数，防止死循环）。

### 4.4 AI 鉴权检索服务

`ai_service.chat_stream` 作为上层门面，负责登录校验、SSE 封装与日志落库。编排层规划交由 `retrieval_graph` 执行，但**本阶段检索链路可先以简化实现兜底**：跳过真实向量召回，直接以「关键词/最近更新知识单元」作为召回候选，重点验证「登录态校验 → 权限鉴权 → 未授权提示 → 流式回答 → 日志落库」整条鉴权闭环；后续替换为 LangGraph 工作流即可。

流程（对应需求 7.2）：

1. 校验登录态（`get_current_user`）。
2. FAQ 缓存命中判断（`faq_cache_service.match`）。
3. 召回候选知识单元（本阶段简化实现，后续走 LangGraph `retrieve` 节点）。
4. 调用 `check_units` 鉴权，拆分为授权/未授权两组。
5. 仅授权单元内容组装 Prompt，调用 LLM 流式生成，转为 SSE。
6. 若存在未授权召回单元，在回答中附加权限缺失提示。
7. 异步写入 `qa_access_logs`。

```python
# app/services/ai_service.py
async def chat_stream(question: str, session_id: str, user: User):
    init_state: RetrievalState = {
        "question": question, "session_id": session_id,
        "user_id": user.id, "messages": [("user", question)],
    }

    async def gen():
        unauthorized = []
        async for event in retrieval_graph.astream(init_state, stream_mode="updates"):
            for node, update in event.items():
                if "unauthorized_units" in update:
                    unauthorized = update["unauthorized_units"]
                if "answer" in update and update["answer"]:
                    yield sse(dict(type="delta", content=update["answer"]))
        yield sse(dict(type="meta", unauthorized=unauthorized))
        yield sse(dict(type="done"))
        # 异步落日志
        asyncio.create_task(log_service.record(session_id, user.id, question, ...))

    return StreamingResponse(gen(), media_type="text/event-stream")
```

### 4.5 FAQ 缓存服务

- 审核通过（`published`）的 FAQ 写入 Redis。
- 提问优先精确匹配，其次语义相似度匹配（高于阈值直接命中）。
- 命中后返回标准答案并累加 `hit_count`。

```python
# app/services/faq_cache_service.py
async def match(question: str):
    # 1. 精确匹配
    if exact := await redis.get(f"faq:exact:{question}"):
        return exact
    # 2. 语义相似度匹配
    vec = await embedding_client.embed(question)
    for faq in await faq_service.list_published():
        if cosine(vec, faq.vec) >= settings.FAQ_SIM_THRESHOLD:
            await faq_service.increase_hit(faq.id)
            return faq.answer
    return None
```

## 6. 关键流程时序

### 6.1 知识导入工作流（LangGraph，后续实现）

```
Client → /api/knowledge/import
  → ingestion_graph.ainvoke(files)
    parse（解析文档） → split（切片） → embed（向量化 API） → persist（写库 + 向量索引）
  → 返回 unit_ids
```

### 6.2 AI 鉴权问答流程（本阶段：简化召回实现）

```
Client → /api/ai/chat/stream
  → 校验 JWT（用户、部门、角色）
  → FAQ 缓存命中判断（命中则直接返回）
  → 简化召回候选知识单元（本阶段）
  → 数据权限引擎鉴权（OR 逻辑）→ 授权单元组装 Context
  → LLM 流式生成 → SSE 返回（含未授权单元提示）
  → 异步写 qa_access_logs
```

> 后续版本将「简化召回」替换为 LangGraph `retrieval_graph`（`faq_cache → retrieve → authorize → build_context → generate`，召回不足时 `rewrite` 回环重试）。

### 6.3 知识沉淀闭环

```
APScheduler 定时任务
  → 聚合 qa_access_logs（语义去重 + 频次统计）
  → 频次 ≥ 阈值 → 生成 faqs(status=pending_review, source_type=auto_mined)
  → 管理员 review approve → status=published → 写入 Redis 缓存
  → 相似度 < 阈值 / 无知识支撑 → 生成 knowledge_gaps
```
