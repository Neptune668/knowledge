# 知识库管理平台 —— 云端部署方案

> 部署目标：腾讯云服务器单机 Docker Compose 部署
> 向量化：使用 DashScope API（暂不部署算力云）
> 大模型：使用阿里云 MaaS（qwen3.7-max）
> 更新日期：2026-08-28

---

## 1. 部署架构

```
腾讯云服务器（单机，Docker Compose）
├── Nginx       :80      前端静态页面 + /api 反向代理后端
├── 后端 FastAPI :8000   业务服务（容器内）
├── PostgreSQL  :5432    业务数据库（容器内）
├── Redis       :6379    缓存（容器内）
├── Milvus      :19530   向量库 standalone（容器内）
├── etcd        :2379    Milvus 元数据（容器内）
└── MinIO       :9000    Milvus 对象存储（容器内）

外部依赖（云 API，无需自建）
├── Embedding  → DashScope API（qwen3.7-text-embedding，1024 维）
└── LLM        → 阿里云 MaaS（qwen3.7-max）
```

> 说明：embedding 和 LLM 均通过公网 API 调用，无需在算力云部署。后续如换自建 embedding 服务，只需改 `EMBEDDING_API_URL`。

---

## 2. 服务器选型建议

| 项 | 建议 |
| --- | --- |
| 配置 | 4 核 8 GB（最低 2 核 4GB，但不稳定） |
| 系统盘 | 50 GB SSD |
| 数据盘 | 100 GB SSD（Docker 数据卷，可选） |
| 系统 | Ubuntu 22.04 LTS / CentOS 8+ |
| 带宽 | 5 Mbps 起 |

> Milvus standalone 是内存大户（2~4GB），8GB 是稳定运行的安全线。

## 3. 前置准备

### 3.1 安装 Docker

```bash
# Ubuntu/Debian 一键安装
curl -fsSL https://get.docker.com | sh

# 启动并设置开机自启
sudo systemctl enable --now docker

# 验证
docker --version
docker compose version
```

### 3.2 开放安全组端口

在腾讯云控制台的安全组，**只开放**：

| 端口 | 用途 |
| --- | --- |
| 80 | HTTP（Nginx） |
| 443 | HTTPS（可选，配 SSL 后） |
| 22 | SSH（管理用，建议限制来源 IP） |

> ⚠️ 不要开放 8000/5432/6379/19530/9000 等端口到公网，它们只在容器内部网络互通。

## 4. 部署步骤

### 4.1 上传代码

将项目上传到服务器，例如放到 `/opt/kami`：

```bash
mkdir -p /opt/kami
# 方式一：git clone（推荐）
cd /opt/kami
git clone <你的仓库地址> .

# 方式二：scp 上传
scp -r backend frontend root@服务器IP:/opt/kami/
```

最终目录结构：
```
/opt/kami/
├── backend/
│   ├── app/
│   ├── deploy/
│   │   ├── Dockerfile
│   │   ├── docker-entrypoint.sh
│   │   └── prod/
│   │       ├── docker-compose.yml
│   │       ├── nginx.conf
│   │       ├── .env.prod.example
│   │       └── README.md
│   ├── requirements.txt
│   └── ...
└── frontend/
    ├── login.html
    ├── index.html
    ├── js/
    └── css/
```

### 4.2 配置环境变量

```bash
cd /opt/kami/kami/backend/deploy/prod
cp .env.prod.example .env.prod
vim .env.prod
```

**必改项**：

| 配置项 | 说明 |
| --- | --- |
| SECRET_KEY | 改成随机长字符串（可用 `openssl rand -hex 32` 生成） |
| POSTGRES_PASSWORD | 改成强密码 |
| DATABASE_URL | 密码与 POSTGRES_PASSWORD 保持一致 |
| EMBEDDING_API_KEY | 你的 DashScope API Key |
| LLM_API_KEY | 你的 LLM API Key |

### 4.3 构建并启动

```bash
cd /opt/kami/kami/backend/deploy/prod
docker compose up -d --build
```

首次启动拉取镜像较多，约需 5~10 分钟（取决于网络）。

### 4.4 查看启动状态

```bash
docker compose ps
```

预期状态：

| 容器 | 状态 |
| --- | --- |
| kami-nginx | Up |
| kami-backend | Up |
| kami-postgres | Up (healthy) |
| kami-redis | Up |
| kami-milvus | Up |
| kami-etcd | Up |
| kami-minio | Up |

### 4.5 验证

```bash
# 后端健康检查（容器内）
curl http://localhost:8000/health

# Nginx 转发验证
curl http://localhost/health

# 前端访问
# 浏览器打开 http://服务器IP/ 应看到登录页
```

## 5. 创建管理员账号

```bash
docker exec -it kami-backend python -c "
import asyncio
from sqlalchemy import select
from app.core.database import async_session_factory
from app.core.security import hash_password
from app.models import User, UserRole, Role

async def main():
    async with async_session_factory() as db:
        rid = (await db.execute(select(Role.id).where(Role.role_code=='admin'))).scalar_one()
        u = User(username='admin123', display_name='系统管理员',
                 password_hash=hash_password('1234'), status='active')
        db.add(u); await db.flush()
        db.add(UserRole(user_id=u.id, role_id=rid))
        await db.commit()
        print('管理员创建成功')

asyncio.run(main())
"
```

然后用浏览器访问 `http://服务器IP/`，用刚才的用户名密码登录。

## 6. 数据库初始化说明

后端容器启动时会**自动执行** `init_db`（建表 + 三角色 + 权限码种子），无需手动操作。

如需手动重新初始化：
```bash
docker exec -it kami-backend python -m scripts.init_db
```

## 7. 常用运维命令

```bash
cd /opt/kami/backend/deploy/prod

# 查看所有容器状态
docker compose ps

# 查看后端日志（实时）
docker compose logs -f backend

# 查看 Milvus 日志
docker compose logs -f milvus

# 重启后端
docker compose restart backend

# 更新代码后重新构建后端
docker compose up -d --build backend

# 停止所有服务（保留数据）
docker compose down

# 停止并清空数据（危险！）
docker compose down -v
```

## 8. 数据备份

关键数据存储在 Docker 数据卷：

```bash
# 查看数据卷
docker volume ls | grep kami

# 备份 PostgreSQL
docker exec kami-postgres pg_dump -U root kami > backup_$(date +%F).sql

# 备份 Milvus 数据（复制数据卷）
docker run --rm -v kami_milvus_data:/data -v $(pwd):/backup alpine tar czf /backup/milvus_backup.tar.gz /data
```

建议定期备份 PostgreSQL 数据 + Milvus 数据卷。

## 10. 常见问题排查

| 问题 | 排查方向 |
| --- | --- |
| 后端启动失败 | `docker compose logs backend`，检查 DB 连接 |
| Milvus 内存不足 | 升级到 8GB，或 `docker compose logs milvus` 查看 |
| 登录后接口 401 | 确认前端 `BASE_URL` 为 `/api` |
| embedding 报错 | 检查 `EMBEDDING_API_KEY` 是否正确、是否欠费 |
| LLM 兜底无响应 | 检查 `LLM_API_KEY`、`LLM_MODEL` 配置 |
| 前端样式乱 | 强制刷新浏览器（Ctrl+F5） |
| 数据看板报错 | 确认 `init_db` 已执行（后端启动自动执行） |

## 11. 后续扩展（可选）

当需要自建向量化服务时：
1. 在算力云部署 FastAPI 封装 embedding 模型
2. 修改 `.env.prod` 的 `EMBEDDING_API_URL` 为算力云地址
3. 重启后端：`docker compose restart backend`

无需改代码，只需改配置。
