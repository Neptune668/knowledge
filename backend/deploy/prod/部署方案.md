# 知识库管理平台 —— 云端部署方案（v2）

> 本方案从零开始，逐步可验证，已规避上一版的所有问题。
> 目标：腾讯云 Ubuntu 服务器，Docker Compose 单机部署。
> 向量化：DashScope API ｜ 大模型：阿里云 MaaS ｜ 向量库：Milvus 容器化

---

## 0. 部署前必读（上一版踩坑总结）

| 坑 | 原因 | 本方案如何规避 |
| --- | --- | --- |
| Docker 镜像拉取超时 | Docker Hub 被墙 | 配置国内镜像加速器 |
| 后端反复重启连不上 DB | entrypoint 用 `python -c` 内嵌多行代码引号冲突 | 改用独立 `check_db.py` 脚本 |
| 日志还是旧版 | git pull 没拉到 / 镜像用了缓存 | 明确 git 操作 + `--no-cache` 构建 |
| 目录混乱 `/opt/kami/kami` | clone 时多套一层 | 统一用 `/opt/kami` 单层目录 |

## 1. 服务器准备

### 1.1 安装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
docker --version
docker compose version
```

### 1.2 配置镜像加速器（关键！否则拉不动镜像）

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<-'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net",
    "https://docker.1panel.live"
  ]
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker

# 验证
docker info | grep -A5 "Registry Mirrors"
```

## 2. 上传代码

### 2.1 拉取代码（git 方式）

```bash
# 统一目录：/opt/kami（单层，不要多套）
cd /opt
sudo rm -rf kami   # 清掉之前可能有问题的旧目录
sudo git clone https://gitee.com/Neptune668/kami.git kami
cd /opt/kami
```

### 2.2 验证代码完整

```bash
# 确认关键文件都在
ls backend/deploy/Dockerfile
ls backend/deploy/docker-entrypoint.sh
ls backend/scripts/check_db.py
ls backend/scripts/init_db.py
ls frontend/login.html

# 确认 entrypoint 是新版（含 check_db.py 字样）
grep "check_db.py" backend/deploy/docker-entrypoint.sh
```

> 如果 `grep check_db.py` 无输出，说明代码没更新，执行 `git pull`。

## 3. 配置环境变量

```bash
cd /opt/kami/backend/deploy/prod

# 生成 .env.prod
cp .env.prod.example .env.prod

# 编辑（vim 或 nano）
vim .env.prod
```

**必改的 4 个值**：

```ini
# 1. SECRET_KEY 改成随机字符串
SECRET_KEY=xxxxx随机字符串xxxxx

# 2. 数据库密码（两处保持一致！）
POSTGRES_PASSWORD=你的强密码
DATABASE_URL=postgresql+asyncpg://root:你的强密码@postgres:5432/kami

# 3. Embedding API Key
EMBEDDING_API_KEY=你的-dashscope-key

# 4. LLM API Key
LLM_API_KEY=你的-llm-key
```

> ⚠️ **最容易出错的地方**：`POSTGRES_PASSWORD` 和 `DATABASE_URL` 里的密码必须完全一致。

---

## 4. 启动部署

```bash
cd /opt/kami/backend/deploy/prod

# 彻底清掉旧环境（首次部署可跳过）
docker compose down -v 2>/dev/null || true

# 构建并启动（--no-cache 确保用最新代码）
docker compose build --no-cache backend
docker compose up -d
```

## 5. 验证部署

### 5.1 查看容器状态

```bash
docker compose ps
```

预期：7 个容器都 `Up`，`kami-postgres` 是 `Up (healthy)`。

### 5.2 看后端日志（关键！）

```bash
docker compose logs backend
```

**成功的话**应该看到：
```
=== 后端容器启动 ===
等待 PostgreSQL 就绪...
PostgreSQL 连接成功
初始化数据库...
启动后端服务...
```

**如果还在重试**（「尚未就绪」），说明 DB 连接有问题，执行第 6 节排查。

### 5.3 测试接口

```bash
# 后端直接测
curl http://localhost:8000/health

# 通过 Nginx 测
curl http://localhost/health
```

两个都应该返回 `{"status":"ok","app":"kami-backend"}`。

### 5.4 浏览器访问

浏览器打开 `http://服务器IP/`，应看到登录页。

## 6. 常见问题排查

### 6.1 后端连不上 PostgreSQL

```bash
# 1. 确认配置一致性
grep -E "POSTGRES_PASSWORD|DATABASE_URL" .env.prod

# 2. 确认 postgres 能连
docker exec kami-postgres psql -U root -d kami -c "SELECT 1;"

# 3. 从后端容器测试
docker exec kami-backend python /app/check_db.py
```

第 3 步如果报错，看具体错误：
- 密码错误 → 检查两处密码一致
- 主机名解析失败 → 检查是否同一网络

### 6.2 镜像拉取失败

重新检查加速器配置：
```bash
docker info | grep -A5 "Registry Mirrors"
```
如果没有镜像源，回到第 1.2 节。

### 6.3 前端 502

后端没起来。看 `docker compose logs backend` 定位。

## 7. 创建管理员账号

后端正常启动后：

```bash
docker exec -it kami-backend python -c "
import asyncio
from sqlalchemy import select
from app.core.database import async_session_factory
from app.core.security import hash_password
from app.models import User, UserRole, Role

async def main():
    async with async_session_factory() as db:
        rid = (await db.execute(select(Role.id).where(Role.role_code=='admin'))).scalar_one()
        u = User(username='admin', display_name='系统管理员',
                 password_hash=hash_password('admin123'), status='active')
        db.add(u); await db.flush()
        db.add(UserRole(user_id=u.id, role_id=rid))
        await db.commit()
        print('管理员创建成功')

asyncio.run(main())
"
```

> 把 `admin123` 换成你的密码。

## 8. 日常运维

```bash
cd /opt/kami/backend/deploy/prod

# 查看状态
docker compose ps

# 查看日志
docker compose logs -f backend

# 更新代码后重新部署
cd /opt/kami && git pull
cd backend/deploy/prod && docker compose build --no-cache backend && docker compose up -d

# 重启后端
docker compose restart backend

# 停止
docker compose down
```
