# 知识库管理平台 —— 后端接口文档（前端开发用）

> 版本：v1.0 ｜ 更新日期：2026-08-27
> 服务地址：`http://<host>:8000`
> 在线调试：`http://<host>:8000/docs`（Swagger UI）

---

## 1. 通用约定

### 1.1 基础信息

- **协议**：HTTP / HTTPS
- **数据格式**：JSON（`Content-Type: application/json`）
- **接口前缀**：`/api`
- **字符编码**：UTF-8

### 1.2 统一响应结构

除登录、文件上传、SSE 流式接口外，多数接口返回统一 JSON：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 0 表示成功；非 0 表示失败（业务错误码） |
| message | string | 提示信息 |
| data | any | 业务数据（可为对象、数组或 null） |

> 注：部分接口（如 `login`、`GET /units`）直接返回业务对象，不包 `{code, message, data}` 外壳，以各接口说明为准。

### 1.3 认证方式

除 `POST /api/auth/login` 外，所有接口均需认证。在请求头携带 JWT：

```
Authorization: Bearer <access_token>
```

### 1.4 错误码

| HTTP 状态码 | 说明 |
| --- | --- |
| 400 | 请求参数错误 / 业务校验失败 |
| 401 | 未登录 / 令牌无效或过期 |
| 403 | 无操作权限 / 用户被停用 |
| 404 | 资源不存在 |
| 422 | 参数校验失败 |
| 500 | 服务器内部错误 |

常见业务错误码（`code` 字段）：

| code | 说明 |
| --- | --- |
| 40101 | 用户名或密码错误 |
| 40301 | 用户已被停用 |
| 40001 | 存在子部门，无法删除 |
| 40002 | 部门下存在成员，无法删除 |
| 40003 | 用户名已存在 |
| 40004 | 非法状态值 |
| 40005 | 角色编码已存在 |
| 40006 | 非法状态值 |
| 40007~40009 | 数据权限实体类型校验错误 |
| 40010 | 审核通过必须提供答案 |
| 40011 | 非法 action 值 |
| 40012~40014 | 知识缺口处理校验错误 |
| 40015 | 暂不支持的文件类型 |
| 40016 | 文件编码无法识别 |

## 2. 认证接口

### 2.1 登录

**`POST /api/auth/login`**

请求体：
```json
{
  "username": "admin",
  "password": "123456"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |

响应：
```json
{
  "access_token": "eyJhbGciOi...",
  "user_info": {
    "id": 1,
    "username": "admin",
    "display_name": "系统管理员",
    "department_id": null,
    "department_name": null,
    "roles": ["admin"]
  },
  "permissions": ["user:create", "knowledge:view", "ai:chat", "..."]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| access_token | string | 访问令牌，后续请求放入 Authorization 头 |
| user_info | object | 用户信息 |
| user_info.id | int | 用户 ID |
| user_info.username | string | 用户名 |
| user_info.display_name | string | 显示名 |
| user_info.department_id | int/null | 所属部门 ID |
| user_info.department_name | string/null | 所属部门名称 |
| user_info.roles | string[] | 角色编码列表 |
| permissions | string[] | 权限码列表（前端据此控制菜单/按钮显隐） |

## 5. AI 问答接口

### 5.1 流式问答

**`POST /api/ai/chat/stream`**（需登录，需权限 `ai:chat`）

请求体：
```json
{
  "question": "B530 怎么使用？",
  "session_id": "会话ID（可选，续接历史对话）"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| question | string | 是 | 提问内容 |
| session_id | string | 否 | 会话 ID，为空则新建会话 |

响应：**SSE 流式**（`text/event-stream`）

事件序列：
```
event: meta
data: {"session_id":"...","recalled":[1,2],"authorized":[1],"unauthorized":[2],"used_fallback":false}

event: delta
data: {"content":"回答片段1"}

event: delta
data: {"content":"回答片段2"}

event: done
data: {}
```

**meta 事件字段说明：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| session_id | string | 会话 ID |
| recalled | int[] | 召回的候选知识单元 ID |
| authorized | int[] | 有权限访问的知识单元 ID |
| unauthorized | int[] | 无权限的知识单元 ID |
| used_fallback | bool | 是否走模型兜底（true=未基于知识库回答） |

> - `unauthorized` 非空时，回答末尾会附带权限缺失提示文本。
> - `used_fallback=true` 时，回答开头会说明「以下回答未基于知识库内容」。

### 5.2 会话列表

**`GET /api/ai/sessions`**（需登录）

查询参数：`page`（默认 1）、`page_size`（默认 20）

响应：
```json
{
  "total": 5,
  "items": [
    { "session_id": "abc...", "last_time": "2026-08-27T10:00:00Z" }
  ]
}
```

### 5.3 会话历史消息

**`GET /api/ai/sessions/{session_id}/messages`**（需登录）

响应：
```json
[
  { "role": "user", "content": "问题1", "created_at": "..." },
  { "role": "assistant", "content": "回答1", "created_at": "..." },
  { "role": "user", "content": "问题2", "created_at": "..." }
```

## 附录 C：SSE 流式问答前端接入示例

```javascript
async function chatStream(question, sessionId, token) {
  const resp = await fetch('/api/ai/chat/stream', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`
    },
    body: JSON.stringify({ question, session_id: sessionId })
  });

  const reader = resp.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });

    // 按 SSE 事件边界解析
    const events = buffer.split('\n\n');
    buffer = events.pop(); // 保留不完整的事件

    for (const evt of events) {
      const lines = evt.split('\n');
      const eventLine = lines.find(l => l.startsWith('event:'));
      const dataLine = lines.find(l => l.startsWith('data:'));
      if (!eventLine || !dataLine) continue;

      const event = eventLine.replace('event:', '').trim();
      const data = JSON.parse(dataLine.replace('data:', '').trim());

      if (event === 'meta') {
        console.log('会话ID:', data.session_id);
        console.log('无权限单元:', data.unauthorized);
        console.log('是否兜底:', data.used_fallback);
      } else if (event === 'delta') {
        // 追加回答内容
        appendAnswer(data.content);
      } else if (event === 'done') {
        // 流式结束
        finishAnswer();
      }
    }
  }
}
```
