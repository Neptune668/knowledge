## 1. 目标与范围

### 1.1 目标

实现基于 Milvus 向量库的智能检索问答，优先检索知识库内容，检索结果不足或无命中时由 LLM 模型兜底回答，并强制接入数据权限鉴权。

### 1.2 核心策略（已确认）

| 策略 | 说明 |
| --- | --- |
| 检索优先 | 优先检索 Milvus 向量库，命中则基于知识内容回答 |
| 模型兜底 | 检索结果不足（低于阈值）或无命中时，由 LLM 通用能力兜底回答 |
| 权限鉴权 | 召回结果必须过数据权限引擎，无权限内容不纳入回答并明确提示 |
| 流式输出 | SSE 流式返回 |

### 1.3 范围界定

| 项 | 本阶段（M8） | 说明 |
| --- | --- | --- |
| 向量检索 | ✅ Milvus 稠密向量检索 | 复用 M7 的 collection |
| 关键字检索 | ✅ PostgreSQL 全文检索 | 混合召回兜底 |
| 权限鉴权 | ✅ 复用 M2 权限引擎 | OR 逻辑 |
| LLM 流式 | ✅ 复用 M4 llm_client | 已有能力 |
| FAQ 缓存 | ✅ 入口命中判断 | 复用 M6 能力 |
| 重排 Rerank | 🔶 可选 | 本阶段可先不引入，后续优化 |

## 2. 架构设计

### 2.1 检索问答链路

```
用户提问
  → FAQ 缓存命中判断（命中直接返回标准答案）
  → 混合召回（Milvus 向量 + PostgreSQL 关键字）
  → 数据权限鉴权（授权/未授权拆分）
  → 结果评估（命中是否充分）
      ├─ 充分 → 基于授权知识组装 Context → LLM 生成（知识问答）
      └─ 不足/无命中 → LLM 通用兜底回答（标注"未基于知识库"）
  → SSE 流式返回（含权限缺失提示）
  → 异步写 qa_access_logs
```

### 2.2 兜底判定条件

进入「模型兜底」的情况（满足任一）：
1. 召回结果为空（Milvus + 关键字均无命中）
2. 召回最高相似度低于 `RETRIEVE_MIN_SCORE`（默认 0.55）
3. 授权后的可用知识单元为空（全被权限过滤）

## 3. 工作流设计

### 3.1 状态定义（RetrievalState）

```python
class RetrievalState(TypedDict):
    question: str              # 原始提问
    session_id: str
    user_id: int
    messages: Annotated[list, add_messages]   # 多轮对话
    # 召回
    recalled_units: list       # 召回的知识单元（含切片）
    recalled_chunks: list      # 召回的切片
    top_score: float           # 最高相似度
    # 鉴权
    authorized_units: list
    unauthorized_units: list
    # 生成
    context: str               # 拼装的上下文
    answer: str                # 最终回答
    used_fallback: bool        # 是否走了模型兜底
```

### 3.2 图结构

```
START → faq_cache → retrieve → authorize → route → generate → END
                                                    ↑
                                  召回不足时 → rewrite → retrieve（回环）
```

### 3.3 路由逻辑（核心）

`route` 条件边，在 authorize 后判定：

```python
def route_after_authorize(state) -> str:
    # 1. 无授权知识 → 模型兜底
    if not state["authorized_units"]:
        return "fallback"
    # 2. 最高相似度不足 → 先 rewrite 重试，超限则兜底
    if state["top_score"] < settings.retrieve_min_score:
        if state["retry_count"] < settings.max_retry:
            return "rewrite"
        return "fallback"
    # 3. 知识充分 → 知识问答
    return "generate"
```

## 4. 节点设计

| 节点 | 职责 | 说明 |
| --- | --- | --- |
| `faq_cache` | FAQ 缓存精确匹配 | 命中直接返回标准答案（M6 能力） |
| `retrieve` | 混合召回 | Milvus 向量 + PG 关键字，RRF 融合 |
| `authorize` | 权限鉴权 | 复用 `permission_engine.check_units` |
| `rewrite` | 问题改写 | LLM 改写问题后重召回（限次） |
| `generate` | 生成回答 | 分知识问答 / 兜底两种 Prompt |
| `fallback` | 模型兜底 | LLM 通用能力回答，标注未基于知识库 |

## 5. 检索策略

### 5.1 混合召回

| 路 | 实现 | 说明 |
| --- | --- | --- |
| 向量召回 | Milvus `search`（COSINE） | Top-K，返回 `unit_id` + `content` + `score` |
| 关键字召回 | PostgreSQL `tsvector` 全文检索 | 兜底，防向量漏召回 |

### 5.2 融合

- RRF（Reciprocal Rank Fusion）合并两路结果
- 召回切片按 `unit_id` 聚合为知识单元

### 5.3 权限过滤

- 对召回结果提取 `unit_id` 集合
- 调 `permission_engine.check_units(user_id, unit_ids)`
- 拆分授权/未授权，仅授权内容进入 Context

## 6. 生成策略（含兜底）

### 6.1 知识问答 Prompt（检索充分）

```
你是知识库问答助手，请仅根据以下知识内容回答，不要编造。
知识内容：
{authorized context}

用户问题：{question}
```

### 6.2 模型兜底 Prompt（检索不足/无命中）

```
你是通用问答助手。用户的问题未在知识库中检索到相关内容，
请基于你的通用知识直接回答，并在开头说明"以下回答未基于知识库内容"。

用户问题：{question}
```

### 6.3 权限缺失提示

召回但无权限的单元，在回答末尾附提示（复用 M4 逻辑）。

## 10. 验收标准

- [ ] 优先检索 Milvus 向量库内容，命中则基于知识回答

- [ ] 召回结果强制过权限引擎，无权限内容不纳入且明确提示
- [ ] FAQ 缓存命中时直接返回标准答案
- [ ] SSE 流式返回，meta 含 used_fallback 标识
- [ ] 问答日志完整记录（召回/授权/未授权/兜底标记）
- [ ] 改写回环有次数上限，不无限循环
