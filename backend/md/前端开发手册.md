# 知识库管理平台 —— 前端开发手册

> 版本：v1.0 ｜ 更新日期：2026-08-28
> 上游依据：《需求文档.md》2.9 节、《backend/md/后端接口文档.md》
> 后端服务地址：`http://<host>:8000`（接口前缀 `/api`）

---

## 1. 项目概述

知识库管理平台前端，提供登录认证、组织权限管理、知识维护与导入、AI 对话鉴权工作台、数据看板、知识沉淀六大功能模块。前端需对接后端 RESTful API，并处理 JWT 认证、RBAC 动态菜单/按钮权限、SSE 流式问答等关键机制。

## 2. 用户角色与权限

| 角色 | role_code | 核心职责 |
| --- | --- | --- |
| 系统管理员 | admin | 用户/角色/部门管理、权限分配、看板监控 |
| 知识管理员 | knowledge_admin | 知识导入/编辑/删除、数据权限配置、FAQ 审核、缺口维护 |
| 普通用户 | user | AI 智能问答 |

**前端权限控制原则**：登录后后端返回 `permissions` 权限码列表，前端据此动态渲染菜单与按钮，控制页面可见性与操作可用性。

## 4. 技术对接规范

### 4.1 HTTP 请求封装

- **Base URL**：`/api`
- **认证头**：`Authorization: Bearer <access_token>`（除登录外所有接口）
- **请求拦截器**：统一注入 token
- **响应拦截器**：统一处理错误

### 4.2 统一响应处理

多数接口返回：
```json
{ "code": 0, "message": "ok", "data": { } }
```

> 注意：`login`、`GET /units`、`GET /roles` 等部分接口**直接返回业务对象**（不包外壳），需按接口文档区分处理。

**错误处理**：
- `code == 0` 成功
- `code != 0` 业务错误，展示 `message`
- HTTP 401：token 失效，跳转登录页
- HTTP 403：无权限，提示用户
- HTTP 422：参数校验失败

### 4.3 Token 与登录态管理

1. 登录成功后 `access_token` 存 localStorage（或内存 + 刷新机制）
2. 请求拦截器自动附带 `Authorization` 头
3. 401 时清除 token 并跳转 `/login`
4. 页面刷新时从存储恢复登录态

### 4.4 动态菜单与按钮权限

- 登录响应 `permissions`（权限码数组）决定菜单与按钮显隐
- 权限码清单见接口文档附录 A
- 建议封装 `v-permission` 指令或 `hasPermission(code)` 函数

## 5. SSE 流式问答对接（重点）

### 5.1 协议说明

接口 `POST /api/ai/chat/stream` 返回 `text/event-stream`，事件序列：

```
event: meta
data: {"session_id":"...","recalled":[1,2],"authorized":[1],"unauthorized":[2],"used_fallback":false}

event: delta
data: {"content":"回答片段"}

event: done
data: {}
```

### 5.2 事件字段

| 事件 | 字段 | 说明 |
| --- | --- | --- |
| meta | session_id | 会话 ID（多轮对话时回传） |
| meta | recalled / authorized / unauthorized | 召回/授权/未授权单元 ID |
| meta | used_fallback | 是否模型兜底（true=未基于知识库） |
| delta | content | 回答增量文本，逐段渲染 |
| done | — | 流式结束 |

### 5.3 前端实现要点

1. 使用 `fetch` + `ReadableStream` 或 `EventSource` 解析 SSE（示例见接口文档附录 C）
2. `delta` 事件内容逐段追加到消息气泡，配合 Markdown 渲染
3. `unauthorized` 非空时，展示「权限缺失提示」卡片（后端已在回答末尾附提示文本，前端也可根据 meta 单独渲染）
4. `used_fallback=true` 时，展示「未基于知识库」标识
5. 保存 `session_id`，下次提问回传实现多轮对话

## 8. 关键注意事项

1. **导入是异步的**：上传后必须轮询 `/import/{task_id}` 获取结果，不要期望同步返回。
2. **文件格式限制**：当前后端仅支持 TXT、Markdown，前端需限制文件选择类型并提示。
3. **部分接口无统一外壳**：登录、列表类接口直接返回对象，需按文档处理。
4. **数据权限配置是覆盖式**：提交权限配置时需一次性传完整列表（不是增量）。
5. **部门删除有前置校验**：有子部门或成员时删除会报 400，前端需友好提示。
6. **多轮对话依赖 session_id**：每次提问回传上次的 `session_id` 才能续接上下文。
7. **FAQ 审核通过必须提供答案**：`approve` 时若 `edited_answer` 为空且原答案为空会报 40010。
