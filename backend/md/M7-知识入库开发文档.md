## 1. 目标与范围

### 1.1 目标

实现知识单元的单文件与批量导入，打通「文档解析 → 文本切片 → 向量化 → Milvus 入库」全链路，支持导入任务进度追踪。

### 1.2 范围界定

| 项 | 本阶段（M7） | 说明 |
| --- | --- | --- |
| 文档解析 | ✅ 从简 | 支持 TXT / Markdown；PDF、Word 后续扩展 |
| 文本切片 | ✅ 需要 | 自研 text_splitter |
| 向量化 | ✅ 外部 embedding API | OpenAI 调用方式，1024 维 |
| 向量存储 | ✅ Milvus | M7 负责设计并创建 collection schema |
| 数据权限配置 | ❌ 不在本阶段 | 复用 M3 能力，导入后手动配置 |
| 检索问答 | ❌ 不在本阶段 | 归 M8 |

### 1.3 关键决策（已确认）

| 决策点 | 结论 |
| --- | --- |
| 向量存储 | Milvus（`MILVUS_URL` 配置，token 认证） |
| 向量维度 | 1024（embedding 模型输出） |
| 向量化调用方式 | OpenAI 兼容 `/embeddings` 接口 |
| 切片 | 需要，两层结构（unit + chunk） |
| 文档解析 | 从简（TXT / Markdown 起步） |
| 向量库 schema | M7 负责设计并初始化 collection |

## 2. 架构设计

### 2.1 两层结构

```
knowledge_units（1）──────（N）knowledge_chunks
  文档 = 知识单元             文档切片 = 向量载体
  承载：标题/正文/元数据/权限   承载：切片内容/向量/序号
  存储：PostgreSQL            存储：PostgreSQL（元数据）+ Milvus（向量）
```

- **权限**挂在单元级（`unit_permissions`，M3 已有，不变）
- **向量**挂在切片级，Milvus 中每条记录对应一个切片
- PostgreSQL 存切片元数据（content、序号、unit_id），Milvus 存向量 + 关键字段

### 2.2 数据流转

```
上传文件
  → parse（解析为纯文本）
  → split（切分 → chunks）
  → embed（调用 embedding API → 1024 维向量）
  → persist（写 knowledge_units + knowledge_chunks + Milvus 向量）
```

## 3. 数据模型设计

### 3.1 新增 PostgreSQL 表：knowledge_chunks

```sql
CREATE TABLE knowledge_chunks (
    id          BIGSERIAL PRIMARY KEY,
    unit_id     BIGINT NOT NULL REFERENCES knowledge_units(id) ON DELETE CASCADE,
    chunk_index INT NOT NULL,                -- 切片序号（从 0 开始）
    content     TEXT NOT NULL,               -- 切片文本
    token_count INT DEFAULT 0,               -- 切片 token 估算
    milvus_id   BIGINT,                      -- Milvus 中对应记录的主键（回填）
    created_at  TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_chunks_unit ON knowledge_chunks(unit_id);
```

> `milvus_id` 用于切片 ↔ Milvus 记录的映射，删除/更新时可按此定位。

### 3.2 Milvus Collection 设计（M7 重点）

**Collection 名**：`knowledge_chunks`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INT64（主键，auto_id） | Milvus 自增主键 |
| `chunk_id` | INT64 | 对应 PostgreSQL `knowledge_chunks.id` |
| `unit_id` | INT64 | 对应 `knowledge_units.id`（权限过滤关键字段） |
| `content` | VARCHAR(65535) | 切片文本（检索返回用） |
| `dense_vector` | FLOAT_VECTOR(1024) | 稠密向量 |

**索引**：
- `dense_vector`：`AUTOINDEX` 或 `HNSW`，metric `COSINE`

**关键点**：`unit_id` 字段是 M8 权限过滤的核心，检索结果能直接映射回知识单元。

### 3.3 配置项新增（.env / config.py）

```ini
# Milvus
MILVUS_URL=             # 连接地址
MILVUS_TOKEN=           # token 认证
MILVUS_COLLECTION=knowledge_chunks

# Embedding（OpenAI 调用方式）
EMBEDDING_API_URL=      # /embeddings 完整地址
EMBEDDING_API_KEY=      # API Key
EMBEDDING_MODEL=qwen3.7-text-embedding
EMBEDDING_DIM=1024      # 向量维度
```

`config.py` 新增字段：
```python

embedding_dim: int = 1024
```

## 6. 工作流设计

### 6.1 状态定义（IngestionState）

```python
class IngestionState(TypedDict):
    task_id: str              # 导入任务 ID
    files: list               # [{filename, text}] 解析后的文本
    parsed_docs: list         # [{filename, text}]
    chunks: list              # [{unit_id, chunk_index, content}]
    embeddings: list          # [[float, ...]] 1024 维
    unit_ids: list            # 入库后的知识单元 ID
    errors: list              # 各文件错误信息
```

### 6.2 图结构

```
START → parse → split → embed → persist → END
```

### 6.3 节点职责

| 节点 | 职责 | 输入 → 输出 |
| --- | --- | --- |
| `parse` | 从简解析：TXT/MD 读文本 | files → parsed_docs |
| `split` | 文本切片 | parsed_docs → chunks |
| `embed` | 调 embedding API 向量化 | chunks → embeddings |
| `persist` | 写 PG（unit + chunk）+ Milvus（向量） | → unit_ids |

### 7.3 text_splitter（切片策略）

- 按段落（空行）切分，段落过长时按长度二次切分
- 默认单切片目标长度 500~800 字符，支持重叠
- 记录 `chunk_index` 保持原文顺序

### 7.4 解析从简

- TXT：UTF-8 直接读取
- Markdown：读取原文（不做富文本处理）
- 其他格式：返回「暂不支持」错误，不阻断其他文件
